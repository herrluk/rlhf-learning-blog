先学方法

01 / 窗口到底在维护什么？

滑动窗口是一段连续区间。用两个下标 left、right 表示边界，再用一个状态保存这段区间的信息，例如元素和、零的数量、每个字符的次数。右边加入一个元素时更新状态，左边移出一个元素时撤销它的贡献。

全文统一使用闭区间 [left, right]，长度为 right - left + 1。初始化 left = 0；扫描前可把 right = -1 理解为尚未加入元素。收缩后也可能出现 left = right + 1，此时窗口为空。

下标      0   1   2   3   4
数组      a   b   c   d   e
              L───────R
窗口          [b, c, d]       长度 = 3 - 1 + 1 = 3

右移 R：加入新元素 → 更新状态
右移 L：移出旧元素 → 撤销贡献

先判断能不能滑，再决定怎么滑

  1. 答案是否是一段连续区间？ 子数组、子串是连续的；子序列允许跳过元素，通常不能直接使用这一框架。
  2. 长度是否固定？ 固定长度就按大小进出窗口，如 438、239。
  3. 长度不固定时，能否证明左边界只需向右？ 求最长常用的“至多”条件，在删去元素后仍然合法；求最短常用的“至少”条件，在加入元素后仍然合法。这种性质使被放弃的起点不必重新考虑。
  4. 状态能否增量维护？ 和可以加减，频次可以加一减一。最大值不能简单撤销，需要第 239 题的单调队列。
连续 ≠ 一定能用滑动窗口。

例如 560「和为 K 的子数组」允许负数，扩张时总和可能增大也可能减小，不能仅凭当前和决定移动哪个边界；通常使用前缀和 + 哈希表。滑动窗口依赖的是具体条件，而不只是题目出现了“子数组”。

四个动作，三种基本安排

A. 求最长：不合法才收缩

先扩张；删到合法；最后记录尽可能长的合法窗口。适用于 3、1004、904。

left = 0
for right, x in enumerate(nums):
    加入(x)
    while 窗口不合法:
        移出(nums[left])
        left += 1
    best = max(best, right - left + 1)

B. 求最短：合法就尝试收缩

先扩张；一旦合法，先记录再收缩；直到不合法。适用于 209、76。

left = 0
for right, x in enumerate(nums):
    加入(x)
    while 窗口合法:
        best = min(best, right - left + 1)
        移出(nums[left])
        left += 1

C. 定长：长度超过就移出，完整后回答

left = 0
for right, x in enumerate(nums):
    加入(x)
    if right - left + 1 > k:
        移出(nums[left])
        left += 1
    if right - left + 1 == k:
        处理当前完整窗口()

这里每轮只加入一个元素，上一轮最多长 k，所以超过长度时移出一次就够。以上是思路伪代码；每题后面提供可独立提交的 Python 代码。

计数是另一层问题：为什么能加窗口长度？

对于“至多 k 种”或“正整数乘积小于 k”等条件，收缩到合法后，固定 right，起点在 [left, right] 中的所有子数组都合法。因此这轮新增 right-left+1 个。第 713 题会把这些后缀逐个列出来；第 992 题再用两次“至多”计数构造“恰好”计数。

两个模板为什么不会漏掉答案？

求最长时，不合法窗口的更早起点只会包含更多元素，不能解决重复、零超限或种类超限；收缩到第一个合法起点后，已经获得该右端点的最长候选。求最短时，每次移出一个起点之前，已经记录过以它开头的合法窗口；将来右端点再向右，只会让这个起点对应的窗口更长，因此不必回头。

嵌套 while 为什么通常还是 O(n)？

不要把循环层数直接相乘。right 总共前进 n 次；left 从 0 出发只向右，总共也至多前进 n 次。只要一次入窗、出窗和合法性判断是 O(1)，总时间就是 O(n)。如果每轮重新排序、求和或复制整个窗口，还要计入那些额外成本。239 的证明类似：每个下标只入队一次、出队至多一次。

Python 代码里先认识这几个写法

enumerate(iterable, start: int = 0) -> iterator

输入可迭代对象，返回逐项产生 (下标, 元素) 的迭代器。for right, x in enumerate(nums) 类似 Go 的 for right, x := range nums。

dict.get(key, default=None) -> value

按 key 查询；缺失时返回 default，不会自动插入键。因此 freq[x] = freq.get(x, 0) + 1 同时处理第一次出现和重复出现。直接访问缺失的 freq[x] 会抛出 KeyError。

del freq[x] 删除键，而赋值为 0 会保留它；len(freq) 计算键的个数。list[int]、dict[str, int] 是类型提示，不会自动检查运行时数据。Python 的 s[left:right+1] 切片右端不包含，所以要加 1；本文只在返回子串时切片，不在每轮复制窗口。

3. 无重复字符的最长子串

输入字符串，返回不含重复字符的连续片段的最大长度。字符必须连续，不能跳着选。

第一站先只维护一个条件：窗口里的字符不能重复。

从题意推导窗口规则

让 right 加入一个字符。原窗口没有重复，所以新出现的重复只可能来自这个新字符。只要它的次数大于 1，就从左边逐个移出字符；重新合法后，再更新最大长度。

要始终说得清的状态

收缩结束后，freq 保存当前窗口每个字符的次数，所有次数都不超过 1；left 是当前 right 下能保留的最靠左的合法起点。

Python 完整解法 · 可独立提交
Python 3.10+
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        freq: dict[str, int] = {}
        left = 0
        best = 0

        for right, ch in enumerate(s):
            freq[ch] = freq.get(ch, 0) + 1  # 入窗
            while freq[ch] > 1:            # 重复时持续收缩
                old = s[left]
                freq[old] -= 1
                if freq[old] == 0:
                    del freq[old]
                left += 1
            best = max(best, right - left + 1)

        return best

复杂度：时间 O(n)，每个字符入窗、出窗至多一次；额外空间 O(min(n, |Σ|))，Σ 为字符集。

易错点

把 while 改成 if，会在 abb 中只删掉 a，留下仍然重复的 bb。若用“上次出现位置”优化，则 left 必须取 max(left, 上次位置 + 1)，不能回退。

自测：s = "abba" 时，为什么加入第二个 b 后只移动一次 left 不够？

先移出的是 a，而重复的是 b。要继续移出第一个 b，窗口才能恢复为不重复的 b。

原题：3. 无重复字符的最长子串

209. 长度最小的子数组

输入正整数数组和正整数 target，返回和至少为 target 的最短连续子数组长度；不存在则返回 0。

上一题在“不合法时”收缩；这一题在“已经合法时”尝试收缩，让答案更短。

从题意推导窗口规则

右端点向右扩张，累加 total。一旦 total ≥ target，当前窗口就是一个候选答案：先记下长度，再移出左端元素。继续尝试，直到总和不够。正整数保证扩张不会让总和变小，收缩不会让总和变大。

要始终说得清的状态

total 始终是 [left, right] 的元素和。while 内每次更新答案时，当前窗口都满足 total ≥ target；循环结束时 total < target。

Python 完整解法 · 可独立提交
Python 3.10+
class Solution:
    def minSubArrayLen(self, target: int, nums: list[int]) -> int:
        left = 0
        total = 0
        best = len(nums) + 1  # 不可能达到的长度，表示还没有答案

        for right, x in enumerate(nums):
            total += x
            while total >= target:
                best = min(best, right - left + 1)
                total -= nums[left]
                left += 1

        return 0 if best == len(nums) + 1 else best

复杂度：时间 O(n)，额外空间 O(1)。

易错点

必须在移出左端元素之前更新答案。若数组允许负数，这个模板不再可靠：例如 [1,-1,5]、target = 5，第一次移出 1 后和变成 4 就停下，会漏掉长度为 1 的 [5]。

自测：为什么这一题 while 写 total >= target，而第 3 题 while 写“出现重复”？

求最短需要从一个合法窗口出发，继续缩小并逐个记录候选；求最长需要先消除不合法部分，再用尽可能长的合法窗口更新答案。

原题：209. 长度最小的子数组

438. 找到字符串中所有字母异位词

输入只含小写英文字母的 s 和 p，返回 s 中所有与 p 字母频次相同的子串起点。字母顺序可以不同。

这次窗口长度已经确定：任何答案的长度都必须等于 len(p)，无需试探不同长度。

从题意推导窗口规则

用两个长度为 26 的数组分别保存目标和当前窗口的字母次数。每次加入右端字符；如果长度超过 m，就移出一个左端字符。窗口恰好长 m 时比较两个频次数组，相等就记录 left。

要始终说得清的状态

检查答案时，窗口长度恰好为 m，window 精确对应当前窗口。频次相同同时保证没有缺少目标字符，也没有额外字符。

Python 完整解法 · 可独立提交
ord(ch: str) -> int

输入一个字符，返回 Unicode 码点。题目限定小写英文字母，所以 ord(ch) - ord("a") 映射到 0～25；不能把这段索引代码直接用于中文或大写字母。[0] * 26 创建 26 个零；列表 == 会逐项比较内容。ans.append(left) 原地追加元素，返回 None，不要赋回 ans。

Python 3.10+
class Solution:
    def findAnagrams(self, s: str, p: str) -> list[int]:
        m = len(p)
        if len(s) < m:
            return []
        need = [0] * 26
        window = [0] * 26
        for ch in p:
            need[ord(ch) - ord("a")] += 1

        left = 0
        ans: list[int] = []
        for right, ch in enumerate(s):
            window[ord(ch) - ord("a")] += 1
            if right - left + 1 > m:
                window[ord(s[left]) - ord("a")] -= 1
                left += 1
            if right - left + 1 == m and window == need:
                ans.append(left)
        return ans

复杂度：时间 O(m + 26n)，固定小写字母表下为 O(m+n)；额外空间 O(26)，不计输出。

易错点

异位词比较的是次数，不能只比较集合。比如 aab 与 abb 的字符集合相同，但并非异位词。使用计数字典时，值为 0 的键是否删除也会影响普通字典的相等比较；这里用 26 位数组规避这个问题。

自测：s = "abab"、p = "ab" 的答案为什么不是 [0,2]？

答案是 [0,1,2]。相邻合法窗口允许重叠，起点 1 对应的 ba 也是异位词；找到一次答案后不能让 left 跳过整个窗口。

1004. 最大连续 1 的个数 III

输入只含 0 和 1 的数组，最多把 k 个 0 改成 1，求能获得的最长连续 1 的长度。

把“修改数组”的叙述转成一个窗口约束，就能复用第 3 题的求最长模板。

从题意推导窗口规则

窗口能全部变成 1，当且仅当其中 0 的数量不超过 k。只统计 zeros，不需要真正修改数组。加入右端点后，如果 zeros > k，就从左边收缩，直到预算够用。

要始终说得清的状态

更新 best 时 zeros ≤ k，窗口内部所有 0 都能用预算翻转，所以整个窗口长度就是一个可行答案。

Python 完整解法 · 可独立提交
Python 3.10+
class Solution:
    def longestOnes(self, nums: list[int], k: int) -> int:
        left = 0
        zeros = 0
        best = 0
        for right, x in enumerate(nums):
            if x == 0:
                zeros += 1
            while zeros > k:
                if nums[left] == 0:
                    zeros -= 1
                left += 1
            best = max(best, right - left + 1)
        return best

复杂度：时间 O(n)，额外空间 O(1)。

易错点

“最多 k 次”不等于“恰好 k 次”，zeros < k 也合法。移出 1 不会减少 zeros，所以不能只移动一次 left，也不应把窗口长度当成消耗的预算。

自测：如果 k = 0，算法还需要换一种写法吗？

不需要。碰到 0 后 while 会把它及其左边尚未移出的元素排除；此时可以出现 left = right + 1 的空窗口，长度为 0，随后继续扫描。

原题：1004. 最大连续 1 的个数 III

904. 水果成篮

从数组某个位置开始连续取水果，每个篮子只能装一种水果，一共两个篮子。求最多能连续取多少个。

class Solution:
    def totalFruit(self, fruits: list[int]) -> int:
        freq: dict[int, int] = {}
        left = 0
        best = 0
        for right, x in enumerate(fruits):
            freq[x] = freq.get(x, 0) + 1
            while len(freq) > 2:
                old = fruits[left]
                freq[old] -= 1
                if freq[old] == 0:
                    del freq[old]
                left += 1
            best = max(best, right - left + 1)
        return best

复杂度：时间 O(n)，本题额外空间 O(1)，字典最多暂存 3 种；推广到至多 k 种时为 O(min(n,k+1))。

易错点

不能只用 set：移出一个 1 时，窗口内可能还留着另一个 1。次数降到 0 后必须 del，否则 len(freq) 会把已经离开的种类也算进去。

自测：如果把两个篮子改成 k 个篮子，核心代码哪里要改？

把 while len(freq) > 2 改成 while len(freq) > k，并接收参数 k。入窗、出窗、删除零频次键和更新最大长度的步骤都不变。

class Solution:
    def minWindow(self, s: str, t: str) -> str:
        if not t or len(s) < len(t):
            return ""
        need: dict[str, int] = {}
        for ch in t:
            need[ch] = need.get(ch, 0) + 1
        window: dict[str, int] = {}
        formed = 0
        required = len(need)
        left = 0
        best_left = 0
        best_len = len(s) + 1

        for right, ch in enumerate(s):
            if ch in need:
                window[ch] = window.get(ch, 0) + 1
                if window[ch] == need[ch]:
                    formed += 1

            while formed == required:
                size = right - left + 1
                if size < best_len:
                    best_left, best_len = left, size
                old = s[left]
                if old in need:
                    if window[old] == need[old]:
                        formed -= 1
                    window[old] -= 1
                left += 1

        if best_len == len(s) + 1:
            return ""
        return s[best_left:best_left + best_len]

复杂度：时间 O(n+m)，n、m 分别为 s、t 长度；额外空间 O(|Σt|)，只保存目标字符种类，不计返回字符串。只在最后切片一次，避免反复复制子串。

易错点

formed 统计的是达标的种类数，不是窗口字符总数。加入字符后只有次数“刚好等于 need”时才加 1，多出来的同种字符不重复加。出窗前只有次数“正好等于 need”时才减 1。t = AABC 时必须有两个 A，集合无法表达这个要求。

自测：need[A] = 2，window[A] 从 3 减到 2 时，formed 应该减 1 吗？

不应该，剩下两个 A 仍然满足需求。只有从 2 减到 1 才失去这一种字符的覆盖，所以代码在减频次之前判断 window[old] == need[old]。

713. 乘积小于 K 的子数组

输入正整数数组和 k，返回乘积严格小于 k 的非空连续子数组的数量。这里要的是个数，不是最长长度。

窗口维护方式已经熟悉，新的关键是：固定右端点后，一次能统计多少个答案。

从题意推导窗口规则

右侧加入元素并乘入 product。只要 product ≥ k，就从左边除掉元素。合法后，[left,right] 内以 right 结尾的所有后缀都合法，因为元素至少为 1，移除前缀不会让乘积增大。起点可以取 left 到 right，共 right-left+1 个。

要始终说得清的状态

计数时 product < k，left 是当前 right 下最靠左的合法起点；更靠左的起点都不合法。每个子数组按唯一的右端点归类，因此既不遗漏也不重复。

class Solution:
    def numSubarrayProductLessThanK(self, nums: list[int], k: int) -> int:
        if k <= 1:
            return 0
        left = 0
        product = 1
        ans = 0
        for right, x in enumerate(nums):
            product *= x
            while product >= k:
                product //= nums[left]  # 除掉的就是乘入的整数因子
                left += 1
            ans += right - left + 1
        return ans

复杂度：在题目数值范围与常规整数运算模型下，时间 O(n)，额外空间 O(1)。

易错点

nums[i] ≥ 1 是这套计数推导的前提。k ≤ 1 时不可能有非空合法子数组，直接返回 0，避免空窗口后继续除法。使用 //= 保持整数，不能用 /= 把 product 变成浮点数。

自测：合法窗口 [5,2,6] 为什么这轮只加 3，而不是把它内部全部 6 个子数组都加上？

本轮只统计以新右端点 6 结尾的子数组。其余 [5]、[2]、[5,2] 已经在之前处理它们各自的右端点时计数了，再加就会重复。

992. K 个不同整数的子数组

输入正整数数组和 k，返回恰好包含 k 种不同数字的非空连续子数组个数。重复数字仍属于同一种。

把第 904 题的“限制种类”与第 713 题的“按右端点计数”组合起来，再用集合相减得到恰好。

Python 3.10+
class Solution:
    def subarraysWithKDistinct(self, nums: list[int], k: int) -> int:
        def at_most(limit: int) -> int:
            if limit <= 0:
                return 0
            freq: dict[int, int] = {}
            left = 0
            count = 0
            for right, x in enumerate(nums):
                freq[x] = freq.get(x, 0) + 1
                while len(freq) > limit:
                    old = nums[left]
                    freq[old] -= 1
                    if freq[old] == 0:
                        del freq[old]
                    left += 1
                count += right - left + 1
            return count

        return at_most(k) - at_most(k - 1)

复杂度：两次 O(n) 扫描仍是 O(n) 时间；额外空间 O(min(n,k+1))。

易错点

直接维护“恰好 k 种”再加窗口长度会把不足 k 种的短后缀也算进去。例如 [1,2] 的 [2] 只有一种。k = 1 时需要 at_most(0) = 0。频次降为零后同样必须删除键。

自测：能否用“至多 k 种的最长长度 − 至多 k−1 种的最长长度”求恰好 k 种的最长长度？

不能。集合包含关系支持的是元素个数相减，最大长度没有这种可减性。例如 [1,2]，至多两种最长 2、至多一种最长 1，相减为 1，但恰好两种最长是 2。

239. 滑动窗口最大值

输入数组和窗口大小 k，窗口每次向右移动一格，返回每个完整窗口中的最大值。

最后一站：长度固定并不代表状态好维护。总和可以减去出窗值，但最大值离开后，必须知道谁能接替。

从题意推导窗口规则

用双端队列保存候选最大值的下标，下标递增、对应值严格递减。先移除已经过期的队首；新值到来时，弹出队尾所有小于等于新值的候选，再把新下标入队。窗口完整后，队首对应的值就是最大值。

要始终说得清的状态

每次入队完成后，队列下标都在当前窗口中且递增，对应数值严格递减。被弹出的较小旧值不可能再胜出：新值更大或相等，而且位置更靠右、过期更晚。

q.append(x: int) -> None
q.pop() -> int
q.popleft() -> int

这里 q 是 deque[int]：append 在右端加入下标，pop 移除并返回右端下标，popleft 移除并返回左端下标。两端添加、弹出操作为 O(1)；空队列弹出会抛 IndexError，所以先用 while q and ... 做非空判断。q[0] 与 q[-1] 分别查看两端，不会移除元素。Python 的普通列表没有 popleft；Go 中常用切片配合头指针实现队列。

Python 3.10+
from collections import deque

class Solution:
    def maxSlidingWindow(self, nums: list[int], k: int) -> list[int]:
        q: deque[int] = deque()  # 保存下标；队首到队尾的值递减
        ans: list[int] = []
        for right, x in enumerate(nums):
            left = right - k + 1
            while q and q[0] < left:
                q.popleft()     # 队首下标已不在窗口内
            while q and nums[q[-1]] <= x:
                q.pop()         # 较旧且不更大的候选永久淘汰
            q.append(right)
            if right >= k - 1:
                ans.append(nums[q[0]])
        return ans

复杂度：时间 O(n)，每个下标只入队一次、出队至多一次；额外空间 O(k)，不计输出。

易错点

队列存下标，才能判断过期；队首取最大值，队尾负责淘汰。两种删除原因要分清。不要用 list.pop(0) 模拟高频出队，它要搬移元素；使用 collections.deque 的 popleft()。

自测：遇到两个相等的值，为什么代码保留更新的那个，把旧的弹掉？

它们对最大值的贡献相同，但新的下标更晚过期。用 <= 弹掉旧值可保持严格递减；使用 < 保留相等值也可以正确求解，但队列变为非递增。
