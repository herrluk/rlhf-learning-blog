GRPO、KL 与变体

看清组内比较、归一化权重、KL 期望与梯度的区别。

GRPO 的直觉是：同一道题生成多个回答，用它们之间的奖励差异构造学习信号。真正影响训练的细节包括分组方式、标准化、长度权重、策略比率和 KL 的梯度路径。

1. 组内优势的完整数值例子

对应面试题：R16、R17、R18、E23、C05。

同一个 prompt 采样 G 个回答，得到 reward R₁…R_G。一种常见的 outcome-based GRPO 优势为 A_i=(R_i-mean(R))/(std(R)+eps)，同一回答的动作 token 共享 A_i。它省去独立 critic，但 reward 仍可来自规则或学习模型。DeepSeekMath

取 reward [0,0,0,1]，明确使用总体标准差，即方差分母为 G：均值为 0.25，标准差为 sqrt(0.1875)≈0.433，优势约为 [-0.577,-0.577,-0.577,1.732]。如果不除标准差，优势为 [-0.25,-0.25,-0.25,0.75]。方向相同，但更新规模不同。

再比较两组 [0,1] 与 [0,10]。各自标准化后都得到 [-1,1]，保留了相对排序，却消除了原奖励跨度。去掉标准差后，大跨度组对梯度的影响更强。某些奖励设置下，逐题标准化还会引入难度相关的权重偏差，因此需要把奖励量纲、组方差和 batch 组成一起检查。TRL GRPO 的标准化说明

如果一组 reward 全为 0 或全为 1，中心化后的优势为零，该组不再提供此项策略梯度；KL、entropy 或其他目标仍可能更新参数。G=1 同样没有组内比较信号，不能只靠加 epsilon 解决。标准差的 correction、epsilon、最小 group size 和无效样本处理应明确记录。

更大的 G 提高看到差异的机会，也增加生成和验证成本，并可能减少固定 token 预算下覆盖的 prompt 数。应记录有信号组比例、每组 token 成本和固定时间下的质量，而不是直接把 G 翻倍视作更强训练。

2. RLOO 与 ReMax 的 baseline

对应面试题：E24。

RLOO 对回答 i 使用其他回答 reward 的均值：b_i=(sum R-R_i)/(G-1)，优势为 R_i-b_i。在 G>1 时，它等于 G/(G-1)*(R_i-组均值)。排除当前样本使 baseline 的独立性更容易分析，但这个关系不包含额外的标准差归一化。RLOO / REINFORCE

ReMax 使用同 prompt 的 greedy response 奖励作为 baseline，再比较采样回答与 greedy 的表现。它需要计算这个参考回答，不要把“省去 critic”误解为没有额外生成成本。ReMax

比较三种方法时，应固定总 rollout/验证预算，分别记录 baseline 方差、额外生成、有效梯度比例与质量。不同 baseline 的最优参数未必相同，不能只替换公式后保留所有超参就宣布算法优劣。

3. Token mean 与 sequence mean 会改变权重

对应面试题：R19、E37。

设有两条回答，长度分别为 2 和 8，所有位置都有效。Sequence mean 先对每条回答的 token loss 求平均，再对两条回答平均：短回答中每个 token 权重为 1/4，长回答每个为 1/16。Token mean 则将 10 个 token 一起平均，每个权重都是 1/10。

前者让每条回答总权重相同；后者让长回答获得更多总权重。二者都可能有明确目的，但不是“只是 reduction 写法不同”。在变长多卡训练中，还要避免每个 rank 先做局部平均，再平均 rank，形成第三种隐含权重。

过滤全同 reward 组可能减少无信号更新，却也使训练更集中于模型当前能产生对错差异的题目；过滤超长回答可能偏向容易短答的任务。丢弃整组、仅丢弃一条、保留上下文但 mask loss 的效果不同。应保存过滤原因、保留率及过滤前后的任务/长度分布。DAPO

4. KL 的方向和 k1/k2/k3

对应面试题：R08、R27。

固定一个上下文，令 p 为当前策略、q 为参考策略，目标为 KL(p||q)=sum_a p(a)log(p(a)/q(a))。它对方向敏感。完整词表求和较直接，但额外存储或计算很大；使用已采样动作估计时，要明确动作来自哪个分布。

定义 ell=log p(a)-log q(a)，且这里假设 a~p、两个分布满足所需支持集条件：

名称 样本表达式 数值性质
k1 ell 期望是 KL，单个样本可为负
k2 0.5*ell² 非负，通常有偏，小变化下可近似
k3 exp(-ell)+ell-1 非负，在这些采样条件下期望是 KL

k3 的证明很短：E_p[q/p-1]=sum q-sum p=0，所以加上这个控制变量不改变 k1 的期望；非负性来自 z-log(z)-1≥0。如果 top-p 截断导致 p 的支持集不覆盖 q，求和关系需要重新检查，不能直接照搬该结论。相关实现与近似见 TRL GRPO。

取 p=[0.8,0.2]、q=[0.5,0.5]。精确 KL 约为 0.192745；k1 两个取值约为 0.4700、-0.9163；k3 两个取值约为 0.0950、0.5837。按 p 加权平均，k1 与 k3 都回到 0.192745。第 10 章提供这个计算的可运行验证。

若样本实际来自旧策略 b，则直接对这些数取平均是在求 E_b[...]，不是 E_p[...]。重要性修正需要正确的分布比率和支持集，也可能有很高方差。公式中用 pi_theta 命名并不能自动让数据成为 current-policy 样本。

5. 无偏 KL 数值不等于无偏 KL 梯度

对应面试题：E36、R09。

这是 RL Infra 很容易忽略的区别。E_p[f_theta(a)] 的梯度既包含 f 本身的导数，也包含采样分布 p 随 theta 变化的项：

grad E_p[f] = E_p[grad f + f*grad log p]

在固定采样 token 上直接 autograd，通常只看到了第一项。以 k1 为例，固定样本求导得到 grad log p，在 p 下的期望为零；但 KL 对 theta 的真实梯度通常不为零。由此可见，数值估计正确并不足以证明梯度实现正确。

KL 放进 reward，通常先用它改变回报/advantage，再经策略梯度影响更新；KL 作为独立 loss，则按那个计算图产生梯度。采样策略、detach、重要性权重、baseline 和归一化都可能使两种写法不同，不能只比较前向打印出来的 KL 数值。

当 KL 飙升，先看它与谁比较、是否被重复惩罚、是否在同一 mask 上平均。然后按版本、长度与任务分桶，核对 tokenizer、旧概率是否误刷新、学习率与更新次数、reward 尺度以及后端差异。先复算小批 token 的概率和目标，再决定是否调整 KL 系数。verl rollout correction

6. 旧样本、采样温度与组关系

对应面试题：R20、E27、E28。

假设原模型给三个 token 概率 [0.5,0.3,0.2]，top-p 保留前两个候选后，真实采样概率变成 [0.625,0.375,0]。采到第一个 token 时，模型原始 log-prob 是 log(0.5)，采样分布 log-prob 是 log(0.625)，两者不相同。保存字段必须区分原始模型、温度缩放和截断重归一化后的概率。

对于旧回答，至少记录行为策略版本、采样配置、reward 版本、prompt/group/sample ID。把几轮之前的答案塞入新 group，会同时改变行为分布和组基线的组成。即使单条样本加了重要性权重，也没有自动修复奖励不可比、选择偏差或不完整 group。

完整轨迹的重要性比率可以涉及多个动作概率的乘积，长轨迹方差容易增大；逐 token 比率又依赖具体 surrogate 的假设。工程实现应说明目标层级和采用的偏差—方差折中，避免宣称某个 clip 参数能“完全消除 off-policy”。AReaL

7. GRPO、DAPO、GSPO 应按修改项比较

对应面试题：R25、E40。

维度 基础 GRPO 常见设置 DAPO 论文中的重点 GSPO 论文中的重点
信号来源 组内相对 reward 保留组比较，并调整样本选择 组内相对 reward
比率/裁剪 token 比率和裁剪 Clip-Higher 等裁剪调整 序列级比率及裁剪
长度权重 原始形式常先按序列平均 token 级 loss 归约 序列级目标与长度归一化比率
样本处理 依实现 dynamic sampling、超长样本处理 关注长序列比率的稳定性

表格对应论文设计，不代表所有名为 GRPO 的框架配置相同。GSPO 使用序列 log-prob 差的长度归一化形式，例如 s_i=exp(mean_t(logpi_theta-logpi_old))；这是几何平均意义的比率，不是未经归一化的整条轨迹概率比。不要再额外宣称该长度归一化自动保留全部无偏重要性采样性质。GSPO、DAPO

比较算法时可以先锁定优势和数据，只替换比率粒度；再固定比率比较过滤。记录实际 loss 版本、长度处理、KL 和 group 逻辑，否则同时改六个选项，无法解释收益来自哪里。

8. 熵坍塌与奖励饱和不是同一件事

对应面试题：E26。

一个策略可以生成很多不同但全错的回答，此时 reward 全为零而熵仍高；也可以总生成几乎同一个正确答案，此时熵低但 reward 高。两者都需要结合任务判断，不能看到熵下降就直接宣布训练失败。

训练 entropy bonus 在目标中鼓励分布熵；提高采样温度是在数据生成阶段改变行为分布。两者作用位置不同，提高温度不等于给优化器加入熵正则。应一起监控 token 熵、重复度、语义多样性、答案长度、任务成功率和有信号组比例。
