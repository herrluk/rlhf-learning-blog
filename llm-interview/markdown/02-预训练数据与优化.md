## 1. 自回归目标、label shift 与 MTP

<!-- q: P01 E06 -->

<!-- question-links:start -->
对应面试题：[P01](../面试题库/02-预训练与分布式训练.md#P01)、[E06](../面试题库/09-全网扩展-基础预训练与SFT.md#E06)。
<!-- question-links:end -->

对于 token 序列 `x₀,x₁,…,x_L`，自回归模型最大化每个 token 在历史前缀条件下的概率，训练 loss 是对应的负 log-prob 之和或平均。Teacher forcing 让所有位置使用真实前缀，因此可并行计算多个位置的预测；因果 mask 确保位置 t 看不到作为目标的未来 token。

例如输入 `[BOS,A,B]`，目标应是 `[A,B,EOS]`。有些模型的 forward 内部完成 shift，手写 loss 时则需自己切片。若两处都 shift，会把“预测下一个 token”错成更远位置；若完全不 shift，模型可能通过当前位置的信息学习无意义的复制。

MTP 增加预测更远未来 token 的训练目标，可以有多个预测头或带依赖的预测模块。它不是把相同 CE 多算几次，也不自动等价于投机解码；后者需要目标模型验证候选 token 的机制。面试时先指定所讨论的 MTP 设计，再讲参数共享和推理用法。[Multi-Token Prediction](https://arxiv.org/abs/2404.19737)

## 2. 清洗与去重：每一步都在改变训练分布

<!-- q: P02 E02 E03 E04 E05 -->

<!-- question-links:start -->
对应面试题：[P02](../面试题库/02-预训练与分布式训练.md#P02)、[E02](../面试题库/09-全网扩展-基础预训练与SFT.md#E02)、[E03](../面试题库/09-全网扩展-基础预训练与SFT.md#E03)、[E04](../面试题库/09-全网扩展-基础预训练与SFT.md#E04)、[E05](../面试题库/09-全网扩展-基础预训练与SFT.md#E05)。
<!-- question-links:end -->

可以把数据流水线画成：解析原文 → 统一格式 → 规则过滤 → 质量筛选 → 精确/近似去重 → 数据分桶 → 编码与打包。这个顺序只是起点，实际应根据成本和误删率调整。例如先去掉明显乱码可降低质量模型调用成本，但过强的规则可能提前删除有价值的代码或数学表达。

精确去重比较规范化后的内容哈希；MinHash 近似估计集合的 Jaccard 相似度，常配合 LSH 找候选。需要明确“集合”是字符 shingle、词 shingle，还是其他特征。同一文本只多几个空白，若预处理删除了空白，表示可能不变；若空白进入 shingle，就可能改变相似度。不能只看算法名称下结论。[DataTrove](https://github.com/huggingface/datatrove)

近似相似关系通常不具传递性：A 与 B 有 80% 重合，B 与 C 有 80% 重合，并不能推出 A 与 C 也达阈值。如果系统将候选图的连通分量视为重复簇，会做更强的合并；需抽检簇内最远的文档，选择代表文档保留策略。MinHash 签名碰撞也只是候选证据，不是原文相等的证明。

表格解析同样影响信息质量。一个跨行单元格可能同时限定几行的含义，直接展平成文本可能丢失关联。可选择保留 HTML、展开表头后转 Markdown，或输出结构化键值。验收时用带合并表头、空值和嵌套表格的固定案例，比较关系是否保留及 token 成本。

工程报告至少记录每阶段输入数、保留率、处理速度、规则版本和抽检结果。例如某过滤器总保留率为 90%，但代码子集只剩 30%，总体数字会掩盖明显的分布偏移。

## 3. 数据配比、规模与小实验怎样联系

<!-- q: P03 P04 P20 -->

<!-- question-links:start -->
对应面试题：[P03](../面试题库/02-预训练与分布式训练.md#P03)、[P04](../面试题库/02-预训练与分布式训练.md#P04)、[P20](../面试题库/02-预训练与分布式训练.md#P20)。
<!-- question-links:end -->

数据配比可以按领域、语言、来源质量和难度定义。采样权重不等于原始数据量占比：一个很小的高质量集合可能被重复很多轮，因此要同时看唯一 token 数和实际曝光次数。比较两个配方时，固定总训练预算和评估集，避免“多训练了 30% token”被误认为配比更好。

对于稠密 Transformer，常用 `C≈6NT` 粗略估计训练计算量，N 为参数量，T 为训练 token 数。这个估计忽略或简化 Attention、embedding、重计算等开销，适合预算推导，不能替代 profiler。计算最优研究强调模型规模与数据规模共同增长；实际还需考虑数据质量和上线推理成本，不能把某个 token/parameter 比值当永恒常数。[Chinchilla](https://arxiv.org/abs/2203.15556)

低成本验证应分层：先用规则与人工抽检确认内容有效，再做小模型或短程实验，最后在目标规模上验证。小实验若只覆盖短文本，会漏掉长文本 packing 和 Attention 的问题；小模型的最优配比也不一定直接迁移到大模型。

一组可复用的对照是：同一训练起点、相同有效 token 数、相同学习率计划，分别使用原配方、候选配方和去掉某类数据的消融。报告领域能力、通用能力、重复度与污染检查，而非只比较训练 loss。

## 4. Packing、代码仓库与数据边界

<!-- q: P05 P19 E13 -->

<!-- question-links:start -->
对应面试题：[P05](../面试题库/02-预训练与分布式训练.md#P05)、[P19](../面试题库/02-预训练与分布式训练.md#P19)、[E13](../面试题库/09-全网扩展-基础预训练与SFT.md#E13)。
<!-- question-links:end -->

假设最长训练长度为 4096，而样本平均只有 500 token，直接 padding 会浪费大量槽位。Packing 将多个样本装入长序列，提高有效 token 比例，但必须先决定跨样本是否可见。

一种语义是把文档串联成连续语料，允许跨文档条件化，并用分隔符表达边界；另一种语义是独立样本训练，使用 block-diagonal causal mask 阻止跨样本 Attention，并处理 position ID 重置。两者都可以有明确目标，但不能声称“拼接后加 EOS 就保证相互独立”。

代码语料还涉及文件顺序、路径、语言、许可证范围和仓库版本。若目标是学习跨文件关系，可保留模块路径并按依赖或项目结构组织；若随机打散所有文件，模型更难获得完整项目上下文。评测切分最好考虑仓库或其派生关系，避免同项目近重复文件同时进入训练与验证。

分布式 sampler 在样本数无法整除 rank 数时，可能丢弃尾部，也可能补齐索引。例如 5 个样本分给 2 个 rank，要求每个 rank 同样步数时，保留全部样本可能需要 6 个位置，其中一个重复。Sampler 的 `drop_last` 与 DataLoader 的 batch 丢尾控制的是不同层面。每个 epoch 的 shuffle、流式 shard 游标和随机状态都要进入恢复设计。[PyTorch 数据加载](https://docs.pytorch.org/docs/stable/data#torch.utils.data.distributed.DistributedSampler)

## 5. AdamW、学习率与混合精度的更新顺序

<!-- q: P06 P07 E07 E14 -->

<!-- question-links:start -->
对应面试题：[P06](../面试题库/02-预训练与分布式训练.md#P06)、[P07](../面试题库/02-预训练与分布式训练.md#P07)、[E07](../面试题库/09-全网扩展-基础预训练与SFT.md#E07)、[E14](../面试题库/09-全网扩展-基础预训练与SFT.md#E14)。
<!-- question-links:end -->

Adam 对梯度的一阶与二阶矩做指数滑动平均，再进行偏差校正和自适应缩放。用 g 表示当前梯度：

```text
m_t = beta1*m_(t-1) + (1-beta1)*g
v_t = beta2*v_(t-1) + (1-beta2)*g²
m_hat = m_t / (1-beta1^t)
v_hat = v_t / (1-beta2^t)
theta = (1-lr*weight_decay)*theta - lr*m_hat/(sqrt(v_hat)+eps)
```

最后一行体现 AdamW 的解耦衰减。若将 L2 梯度直接混入 g，它会参与自适应矩估计，通常不等价于独立参数衰减。bias、归一化参数是否衰减属于参数分组策略，应与公式本身区分。[AdamW](https://arxiv.org/abs/1711.05101)

Warmup 逐步增加学习率；稳定阶段维持一定更新强度；退火在后期减小步幅。这些设计需要结合有效 batch、训练预算及初始化选择。恢复中断应恢复 scheduler 的进度；新增一批数据继续训练则是新的预算决策，不能自动重置为第 0 步。[Transformers 调度器](https://huggingface.co/docs/transformers/main_classes/optimizer_schedules)

FP16 的指数范围较窄，训练中常用 loss scaling 缓解梯度下溢；BF16 的指数范围接近 FP32，但有效精度较低。选择 BF16 不代表所有计算都能使用 BF16，归约、优化器状态和某些敏感算子可能仍需要较高精度。

若使用 GradScaler 和梯度累积，典型顺序为：多个 micro-batch 的 scaled backward → 在更新边界 unscale → 检查/裁剪梯度 → 有效 optimizer step → 更新 scaler → 按计划推进 scheduler。提前逐 micro-batch 裁剪与对累积后的总梯度裁剪通常不等价。发生 overflow 并跳过 optimizer step 时，scheduler 是否应推进必须与其计步语义一致。[PyTorch AMP](https://docs.pytorch.org/docs/2.14/notes/amp_examples.html)

## 6. Loss spike 与 NaN 应怎样排查

<!-- q: P16 -->

<!-- question-links:start -->
对应面试题：[P16](../面试题库/02-预训练与分布式训练.md#P16)。
<!-- question-links:end -->

第一步区分“日志突然变大”和“参数真的异常”。保存故障前后的样本 ID、长度、token 数、LR、梯度范数、loss scaler、模型版本，以及各 rank 的局部指标。只有全局平均值时，很容易漏掉单个 rank 的异常输入。

按可检验的假设推进：先复现同一 batch，再检查 label/mask 和空分母；定位第一个非有限张量；比较更高精度或关闭某个 fused kernel 后的结果；最后检查通信和硬件。若是长文本或特定代码样本触发，只降低 LR 会掩盖根因。

例如只有某批次某 rank 没有有效目标 token，局部 loss 写成 `sum/count` 会得到 0/0，随后污染梯度。修复应明确定义空 batch 的行为并保持 collective 一致，而不是简单在出现 NaN 后跳过该 rank。
