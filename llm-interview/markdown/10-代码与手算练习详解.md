## 1. 最小多头 Attention：先检查形状和 mask

<!-- q: C01 -->

<!-- question-links:start -->
对应面试题：[C01](../面试题库/06-手撕与白板练习.md#C01)。
<!-- question-links:end -->

下面支持同维度的 self-attention 和 cross-attention。`allowed` 使用 True 表示可见；cross-attention 的复杂可见关系由调用方显式提供。没有实现 dropout、KV Cache、RoPE 或 GQA。

```python
import math
import torch
from torch import nn

class MultiHeadAttention(nn.Module):
    def __init__(self, dim, heads):
        super().__init__()
        if dim % heads:
            raise ValueError("dim 必须能被 heads 整除")
        self.heads, self.head_dim = heads, dim // heads
        self.q = nn.Linear(dim, dim, bias=False)
        self.k = nn.Linear(dim, dim, bias=False)
        self.v = nn.Linear(dim, dim, bias=False)
        self.out = nn.Linear(dim, dim, bias=False)

    def split(self, x):
        b, length, _ = x.shape
        return x.reshape(b, length, self.heads, self.head_dim).transpose(1, 2)

    def forward(self, x, context=None, causal=False, allowed=None):
        if causal and context is not None:
            raise ValueError("cross-attention 的可见关系请用 allowed 显式传入")
        context = x if context is None else context
        q, k, v = self.split(self.q(x)), self.split(self.k(context)), self.split(self.v(context))
        b, h, lq, d = q.shape
        lk = k.shape[-2]
        visible = torch.ones((b, 1, lq, lk), device=x.device, dtype=torch.bool)
        if causal:
            visible = visible & torch.ones((lq, lk), device=x.device, dtype=torch.bool).tril()
        if allowed is not None:
            # allowed 必须可广播到 [B,1或H,Lq,Lk]，例如 [B,1,Lq,Lk]。
            visible = visible & allowed.to(device=x.device, dtype=torch.bool)
        scores = (q.float() @ k.float().transpose(-1, -2)) / math.sqrt(d)
        scores = scores.masked_fill(~visible, -torch.inf)
        any_key = visible.any(dim=-1, keepdim=True)
        scores = torch.where(any_key, scores, torch.zeros_like(scores))
        p = torch.softmax(scores, dim=-1).masked_fill(~visible, 0.0)
        y = (p @ v.float()).to(x.dtype)
        y = y.transpose(1, 2).contiguous().reshape(b, lq, h*d)
        return self.out(y)
```

Q 和 K 的转置作用于最后两个维度，因此分数是 `[B,H,Lq,Lk]`；softmax 沿 key 位置归一化。全 mask 行先将 scores 置为可计算的零，再把概率置零，避免 `softmax([-inf,...])` 产生 NaN。该策略定义了空可见集合的输出为零，不代表所有库都采用相同约定。

验证至少要包括：self-attention 的输出形状；改变未来 token 不影响较早位置；cross-attention 的 Lq≠Lk；一整行不可见；与逐头朴素实现的数值对照。使用 KV Cache 时还要给 query 的绝对位置，不能对一个 `Lq=1,Lk=100` 的 decode 分数矩阵直接套本例 self-attention 的左上三角语义。[PyTorch SDPA](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.scaled_dot_product_attention.html)

## 2. CPT 与 SFT 共享 CE，目标 mask 不同

<!-- q: C02 C09 -->

<!-- question-links:start -->
对应面试题：[C02](../面试题库/06-手撕与白板练习.md#C02)、[C09](../面试题库/06-手撕与白板练习.md#C09)。
<!-- question-links:end -->

下面假设模型返回未 shift 的 logits，不调用模型内部的 labels/loss 接口。输入 ID 全部是有效词表 ID，padding 的排除由 mask 完成。

```python
import torch.nn.functional as F

def next_token_loss(logits, input_ids, target_mask):
    # logits:[B,L,V]；target_mask 标记 input_ids 中哪些 token 是监督目标。
    pred = logits[:, :-1, :].float()
    labels = input_ids[:, 1:].clone()
    mask = target_mask[:, 1:].bool()
    labels = labels.masked_fill(~mask, -100)
    token_loss = F.cross_entropy(
        pred.reshape(-1, pred.shape[-1]),
        labels.reshape(-1),
        reduction="none", ignore_index=-100,
    ).reshape_as(labels)
    count = mask.sum()
    if count.item() == 0:
        raise ValueError("本教学单卡步骤没有有效目标 token")
    return token_loss.sum() / count
```

CPT 常对所有有效预测目标计算 loss；assistant-only SFT 只选择相应回答 token。Packing 时还要决定文档首 token 是否在当前上下文中有有效预测定义。这里 `count.item()` 会触发设备到主机的同步，是教学上的显式检查；生产环境应设计适合分布式图和性能需求的空目标处理。

分布式作业不能让某个 rank 因空目标直接抛出异常、其他 rank 却继续进入 collective。应在进入更新前统一判定，或按全局分母保留连接计算图的零贡献。第 8 章给出了正确归一化推导。

## 3. PPO、GAE、GRPO 与 DPO 的关键行

<!-- q: C03 C04 C05 C06 -->

<!-- question-links:start -->
对应面试题：[C03](../面试题库/06-手撕与白板练习.md#C03)、[C04](../面试题库/06-手撕与白板练习.md#C04)、[C05](../面试题库/06-手撕与白板练习.md#C05)、[C06](../面试题库/06-手撕与白板练习.md#C06)。
<!-- question-links:end -->

PPO 核心是 `min(ratio*A, clipped_ratio*A)`；代码中若做梯度下降，还需要取负。可以在四个远离裁剪拐点的数值上做有限差分，检查对 ratio 的导数分别为 0、1、-1、0。这比只比较 forward loss 更容易发现错误分支。

GAE 从后往前扫描，因为 A_t 依赖 A_(t+1)。纯 Python 示例分开 bootstrap 和 trace mask，并用三步手算值 `[0.676,0.64,0.6]` 核对。另一个测试把截断片段后放入 reward=99 的独立样本，检查前一片段不会错误吸收它。

GRPO 示例显式使用总体标准差，不调用带隐含 correction 的默认函数；G=1 抛出错误，全同 reward 返回零优势。生产中还要按 group ID 聚合，不能假设一个 batch 每连续 G 条必然来自同一 prompt，尤其是在异步与重排之后。

DPO 使用稳定的 `softplus(-beta*margin)`，避免直接计算很小 sigmoid 再取 log。示例验证 chosen 从 0.20 降到 0.18、rejected 从 0.20 降到 0.10 时，loss 仍可降低。自动微分版本需要 reference 与 old 数据按设计 detach，但不能把 current log-prob 一起 detach。

## 4. AdamW 和多卡归一化的验收

<!-- q: C07 C08 -->

<!-- question-links:start -->
对应面试题：[C07](../面试题库/06-手撕与白板练习.md#C07)、[C08](../面试题库/06-手撕与白板练习.md#C08)。
<!-- question-links:end -->

`adamw_scalar` 用一个参数验证偏差校正和独立衰减。初始 theta=1、g=2、m=v=0，第一步校正后的一阶矩为 2、二阶矩为 4，所以自适应更新项接近 lr，而非 2lr。若漏掉偏差校正，第一步数值会明显不同。

多卡例子应同时对照 loss 数值和梯度。令各 token 的 loss 为 `a_i*theta`，则全局目标的梯度直接等于所有 a_i 的平均数。把这些 token 不均匀分到两个 rank，再使用 `W*S_r/N`，DDP 平均后的梯度应与拼接计算一致。只用每 rank 相同长度的样本，无法发现 mean-of-means 的错误。

这些测试只核对数学缩放。实际 DDP/FSDP 还要在目标版本中验证梯度累积、自定义 hook、空 rank 与 checkpoint 恢复，不能用纯标量例子替代真实集成验证。

## 5. KL 与 online softmax 的独立对照

<!-- q: R27 E57 -->

<!-- question-links:start -->
对应面试题：[R27](../面试题库/04-RLHF与强化学习算法.md#R27)、[E57](../面试题库/11-全网扩展-RLInfra与手撕.md#E57)。
<!-- question-links:end -->

KL 示例使用完整的两项离散分布直接枚举期望，比较精确 KL、k1、k2、k3。它验证的是采样分布满足假设时的数值性质，不验证训练时 autograd 的无偏性。要验证后者，需把解析梯度、完整词表枚举梯度和具体采样实现分别比较。

Online softmax 示例将 `[1000,1001,999]` 分为两块，再合并最大值和指数和，与整行一次性计算对照。选大 logits 是为了暴露不稳定指数计算；加入空块是为了验证单位元，避免只测试普通输入。

## 6. 一个小型 byte-level BPE

<!-- q: E59 -->

<!-- question-links:start -->
对应面试题：[E59](../面试题库/11-全网扩展-RLInfra与手撕.md#E59)。
<!-- question-links:end -->

纯 Python 示例先把文本转为 UTF-8 字节序列，统计相邻 pair，合并频率最高的 pair，记录 merge rank。编码新文本时按已学到的 rank 选择可合并 pair；解码则拼接 bytes 后进行 UTF-8 解码。

这个版本保留全部字节作为基本符号，所以未见过的 emoji 仍能表示；它不做归一化、不处理生产 tokenizer 的特殊 token 和复杂预分词，输出也直接使用 bytes 块以便观察。测试检查中英文、空白、emoji 和空串的往返一致性。

面试可继续追问：若修改归一化规则，往返还能对原字符串严格相同吗？若 added token 与普通 merge 重叠，应优先哪条规则？词表扩展与模型 embedding 行数如何一起版本化？这些是从小例子迁移到真实 tokenizer 的关键。

## 7. 跨 chunk 的工具调用 JSON 状态机

<!-- q: E60 -->

<!-- question-links:start -->
对应面试题：[E60](../面试题库/11-全网扩展-RLInfra与手撕.md#E60)。
<!-- question-links:end -->

一个网络 chunk 不一定是一个 token、一个字符或一个 JSON 对象。UTF-8 中文字符可能被切在字节中间，字符串内的花括号也不是结构边界。因此示例先使用增量 UTF-8 decoder，再追踪 `in_string`、`escaped`、嵌套 depth 和 complete。

`ToolJSONBuffer` 只接受一个顶层对象；结构完整后继续接收的非空白数据会报错。`finish()` 再交给标准 JSON parser 验证完整语法；深度归零只是边界判断，不足以证明语法正确。测试把中文、转义引号和字符串中的花括号按每 1、2、7 个字节分片输入，并检查不完整载荷被拒绝。

解析成功后仍需校验工具名称、参数 schema、call ID 和调用状态；示例不会执行任何工具。真实协议可能是 SSE、JSON Lines 或模型专用增量字段，必须先按协议组帧，再做对象解析。取消、重试、载荷限制和幂等性也应在执行层处理，不能靠一个 JSON parser 保证。

## 8. CUDA 练习的验收清单

<!-- q: C10 E55 E56 E58 -->

<!-- question-links:start -->
对应面试题：[C10](../面试题库/06-手撕与白板练习.md#C10)、[E55](../面试题库/11-全网扩展-RLInfra与手撕.md#E55)、[E56](../面试题库/11-全网扩展-RLInfra与手撕.md#E56)、[E58](../面试题库/11-全网扩展-RLInfra与手撕.md#E58)。
<!-- question-links:end -->

本轮给出第 9 章的算法分解与边界解释，没有声称交付了经过 GPU 验证的高性能 CUDA 实现。练习时建议按以下顺序推进：

| 题目 | 先实现 | 再验收 | 最后优化 |
| --- | --- | --- | --- |
| Row max | 一 block 一行 | 非整齐列数、NaN 策略、极值 | 向量化加载、warp/block 归约、shape 分流 |
| Histogram | 全局 atomic | 同桶高冲突、空输入、溢出 | block 局部桶与分层合并 |
| Scan/compaction | 局部 scan + block 偏移 | 非 2 的幂、全保留、全丢弃 | 扫描算法与临时缓冲复用 |
| 方差/RMSNorm | 明确统计目标 | 大偏置小方差、低精度、尾部 | 稳定统计、融合与访存 |

每个优化都要与简单参考实现比较，再测设备执行与端到端时间。吞吐数字必须附 GPU、dtype、shape 和数据分布；没有这些条件，所谓“提升 2 倍”难以判断价值。
